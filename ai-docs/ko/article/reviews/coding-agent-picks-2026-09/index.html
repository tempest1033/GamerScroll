플랑크톤2026년 9월 7일

파세오는 원격 접속과 패널, 오르카는 동시 작업의 격리와 원격 환경, 딥시크 하네스는 유연한 플러그인 확장이 강점이다. 9월 눈여겨볼 세 도구가 어떤 사용자에게 맞는지 정리했다.

코덱스와 클로드 코드를 여러 개 띄워 쓰다 보면 모델 성능 외에도 신경 쓸 일이 생긴다. 에이전트마다 진행 상황을 확인하고, 동시에 수정하는 파일이 충돌하지 않도록 작업을 나누고, 필요한 기능을 추가해야 한다. 기본 앱이나 CLI에 관리 도구를 더하는 이유다.

여러 에이전트의 작업을 조율하는 오케스트레이션, 서로 다른 모델·에이전트를 섞어 쓰는 방식도 이런 관리 환경이 필요하다. 계획과 구현, 검토를 각각 맡기려면 작업을 분배하는 데서 끝나지 않고 진행 상황과 결과까지 함께 관리해야 한다.

2026년 9월 코딩 에이전트 도구 세 가지를 이런 기준으로 골랐다. 원격 접속과 멀티패널이 강점인 파세오, 동시 작업의 격리와 원격 환경이 돋보이는 오르카, 플러그인 확장이 유연한 딥시크 하네스다. 공식 문서와 릴리스 기록을 바탕으로 에이전트 관리 방식과 추천 대상을 비교했다.

에이전트를 관리하는 환경부터 실행 기반까지

세 도구는 에이전트를 활용하는 과정에서 서로 다른 부분을 맡는다. 파세오와 오르카는 클로드 코드·코덱스·오픈코드 같은 기존 CLI 에이전트를 실행하고 관리한다. 익숙한 에이전트는 그대로 두고, 여러 세션을 다루는 화면과 원격 접속, 작업 관리 기능을 더하는 방식이다.

딥시크 하네스는 한 단계 안쪽을 다룬다. 모델 호출과 도구 사용을 처리하는 실행 기반을 플러그인으로 구성해, 필요한 기능을 붙이거나 동작을 바꿀 수 있다. 모델 성능과 구독 조건을 고른 뒤에도 관리 환경을 개선할지, 실행 구조까지 손볼지에 따라 선택지가 나뉘는 셈이다.

파세오: 원격 접속과 멀티패널로 작업을 한눈에

이미지 출처: 파세오 공식 홈페이지

파세오는 여러 에이전트의 진행 상황을 한곳에서 확인하고, 원격에서도 작업을 이어가기 좋은 도구다. 멀티패널로 세션을 나란히 펼칠 수 있어 터미널 창을 하나씩 오가는 수고를 줄인다. 기존 에이전트를 바꾸기보다 이를 다루는 환경을 편하게 만드는 데 강점이 있다.

8월 말 업데이트는 이런 방향을 보여준다. 8월 31일 공개된 0.7.0 릴리스에는 데스크톱과 CLI에서 기존 원격 데몬에 SSH로 연결하는 기능이 추가됐다. Git 저장소를 통한 플러그인 설치도 지원하며, 라이선스는 Apache-2.0으로 변경됐다.

여러 에이전트를 함께 쓰는 오케스트레이션 기능도 갖췄다. 공식 문서는 클로드 코드가 코덱스에 하위 작업을 맡기는 예를 든다. 작업 성격에 따라 다른 에이전트를 선택하고, 나뉜 작업의 진행 상황은 같은 앱에서 확인하는 구성이다.

여러 세션을 패널로 펼쳐 놓고 쓰거나, 집과 사무실을 오가며 실행 중인 작업을 확인하는 사용자에게 잘 맞는다. Windows에서는 9월 2일의 0.7.2가 데몬 종료·재시작 후 에이전트 프로세스가 남던 문제를 수정했으므로, 원격 환경을 구성할 때 사용 버전도 확인하는 편이 좋다.

파세오 설치하기

오르카: 작업은 분리하고, 로컬과 원격은 함께 관리

이미지 출처: 오르카 공식 홈페이지

여러 에이전트가 동시에 코드를 수정한다면 각자의 변경 사항을 분리해 관리하는 일이 중요하다. 스태블리의 오르카는 이 작업 격리에 강점이 있다. 공식 저장소는 하나의 프롬프트를 다섯 에이전트에 보내고, 별도의 Git worktree에서 나온 결과를 비교하는 사용법을 소개한다. worktree는 같은 저장소를 서로 다른 작업 폴더와 브랜치로 나눠 쓰는 기능이다.

이 구성을 원격 환경으로도 확장할 수 있다. SSH worktree는 원격 머신의 파일 편집과 Git, 터미널 작업을 지원하며 재연결과 포트 포워딩도 제공한다. 로컬과 원격의 작업을 같은 앱에서 다룰 수 있다는 점이 병렬 실행 못지않은 장점이다.

여러 기능이나 수정안을 동시에 진행하는 개발자, 같은 요청을 서로 다른 에이전트에 맡겨 결과를 비교하는 사람에게 추천한다. 터미널 분할과 클로드·코덱스 사용량 추적도 여러 작업을 관리할 때 도움이 된다.

도입 전에는 지침과 세션 복구 방식을 확인할 필요가 있다. 오르카의 오케스트레이션 가이드는 위임받은 에이전트가 추가된 조정 지침을 따르도록 정한다. 세션 복원 실패 후 탭 상태가 빈 값으로 저장되는 문제가 이슈 #1158에 보고된 만큼, 기존 하네스 설정과의 관계뿐 아니라 사용 버전의 수정 여부와 백업 방법도 살펴보는 편이 좋다.

오르카 설치하기

딥시크 하네스: Pi 대안으로 살펴볼 플러그인 확장성

이미지 출처: 딥시크 하네스 공식 저장소

파세오와 오르카가 기존 에이전트의 작업을 관리한다면, 딥시크 하네스는 에이전트 자체를 구성하는 쪽에 가깝다. 플러그인과 익스텐션을 유연하게 조합할 수 있어, Pi를 기반으로 자신만의 환경을 만들어 온 개발자가 대안으로 살펴볼 만하다.

핵심은 확장할 수 있는 범위다. 공식 아키텍처 문서에 따르면 모델 어댑터, 도구 등록부, 세션 로그, 에이전트 실행 루프까지 Cordis 플러그인으로 구성된다. 도구를 몇 개 추가하는 수준을 넘어, 에이전트가 실행되는 핵심 구조도 설정에서 교체할 수 있다.

실행 형태는 웹 앱, 서버 없는 일회성 실행, SDK, ACP 연결 등의 프로필로 나뉜다. 용도에 맞는 구성을 선택하고 필요한 요소를 조합하는 방식이다. 세션 로그에서 모델에 전달된 내용을 재구성하도록 설계해, 동작을 추적할 수 있게 한 점도 확장 기능을 개발할 때 참고할 만하다.

새로운 도구나 모델 연결을 직접 구현하거나, 에이전트의 동작을 세밀하게 바꾸고 싶은 개발자에게 추천한다. 프로필과 플러그인 구성을 익히는 과정은 필요하지만, 완성된 앱의 설정만으로는 하기 어려운 변경까지 시도할 수 있다는 것이 매력이다.

딥시크 하네스 설치하기

원격 관리, 병렬 작업, 확장성 중 필요한 것부터

여러 에이전트를 섞어 쓰더라도 모두 같은 환경을 필요로 하지는 않는다. 진행 상황을 편하게 확인하는 일이 우선이라면 파세오, 동시에 진행하는 작업의 변경 사항을 나누는 일이 중요하다면 오르카가 먼저 눈에 들어온다. 에이전트에 필요한 기능을 직접 구현하려면 딥시크 하네스의 확장 구조를 살펴볼 만하다.

세 도구의 기능은 일부 겹치지만 지향하는 사용 방식에는 차이가 있다. 원격 관리와 병렬 작업, 플러그인 확장 중 현재 작업에서 가장 필요한 부분을 정하면 새로운 코딩 에이전트 도구를 고르는 기준도 분명해진다.
